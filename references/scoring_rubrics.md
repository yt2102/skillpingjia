# skillpingjia 评分细则详解

> SKILL.md 只列子项分值 + 1.0 标准。本文件给 LLM-as-judge 判 0/0.5/1 三档的**明确范例**，避免每次评估自由发挥。

## 主信号：触发设计 (20 分)

### 显式触发词 (5 分)

| 档位 | 范例 |
|---|---|
| 1.0 | description 含 5+ 同义表达（"打分""评估""评价""复盘""评审"） |
| 0.5 | 含 1-2 个词 |
| 0 | 无任何显式词 |

### 隐式意图 (5 分)

| 档位 | 范例 |
|---|---|
| 1.0 | 含真实话术样例（"你看看我的 skill 怎么样"） |
| 0.5 | 仅有功能描述，无用户绕弯表达 |
| 0 | 只有 trigger word 列表 |

### 核心信号 (4 分)

| 档位 | 范例 |
|---|---|
| 1.0 | 一句话回答"用户想达成什么"（"指导改进优先级"） |
| 0.5 | 偏功能声明（"评估 Skill 质量"） |
| 0 | 完全不提意图 |

### pushy 句式 (1 分)

| 档位 | 范例 |

| 1.0 | "Make sure to use..." / "even if they don't explicitly ask..." |

| 0 | 无 pushy |

### 负触发 (3 分)

| 档位 | 范例 |

| 1.0 | 明列不需要的场景 + "直接答"指示 |
| 0.5 | 仅列不接什么，无降级指示 |
| 0 | 无负触发 |

### 技能互斥 (2 分)

| 档位 | 范例 |

| 0.5 | 单向边界 |
| 0 | 无边界 |

## 流程纪律 (15 分)

### 步骤化管线 (3 分)

`Step 0/1/2...` 或 `→ 链` 标记；每步有明确动作。

### 每步有产出 (3 分)

每步有"产出物"字段（文件路径、消息格式、返参 schema）。

### 失败分级 (6 分) — 2026-08-17 调高

`critical failure` vs `可降级` 区分。例如：
- ✅ 1.0：缺依赖 → ImportError + 解决指引；超 6 天 → ValueError
- ❌ 0.5：只说"可能失败"，无具体异常类型
- ❌ 0：静默截断（示例）

### 禁止路径 (2 分)

"Never call..." 明确不做的动作。

### 打扰预算 (1 分)

澄清 0-2 问 + 默认值静默应用。

## 结构合理性 (20 分)

### SKILL.md <500 行 (5 分)

`wc -l < SKILL.md` 直接数。

### references 拆解 (8 分)

| 档位 | 范例 |
|---|---|
| 1.0 | 拆出 ≥3 份领域知识到 references/ |
| 0.5 | 拆 1-2 份或只引用未拆 |
| 0 | 全部塞 SKILL.md |

H4 命中时此项直接归 0。

### scripts 确定性 (7 分)

| 档位 | 范例 |
|---|---|
| 1.0 | 脚本接管渲染/计算，模型只写 JSON |
| 0.5 | 脚本只做部分（如只算分不渲染） |
| 0 | 完全是 LLM 直出成品 |

## 输出契约 (15 分)

> **判据问本质，不问形式**：中间表示可以是 JSON / YAML / dict / 任何数据层，不限定文件格式。
> 判 1.0 必须三个本质问题都能答「是」：
> ① 中间表示能否独立于渲染逻辑存在？
> ② 改数据能否不碰渲染代码就出新版？
> ③ 中间表示能否被独立校验（合法/完整）？

### 结构化中间表示 (5 分)

| 档位 | 判据 |
|---|---|
| 1.0 | 模型产数据、脚本产成品，数据层独立存在（文件/变量/数据层不限形式） |
| 0.5 | 函数式 API 封装（add_heading 直接调用）或数据嵌在代码里，数据与渲染耦合 |
| 0 | 模型直出成品格式（手写 Word/HTML） |

**常见实现（不限于此）**：lesson.json 落盘 → 脚本读文件渲染；structure dict → 脚本渲染（若 dict 独立于渲染代码且可重跑）。

### 可校验 (3 分)

| 档位 | 判据 |
|---|---|
| 1.0 | 输出可 0/1 判分（JSON 合法性 / 文件存在性 / 字段值 / 成品验证） |
| 0.5 | 部分可校验 |
| 0 | 不可校验 |

### 可重渲染 (3 分)

| 档位 | 判据 |
|---|---|
| 1.0 | 改数据/中间表示秒出新版，不碰渲染逻辑 |
| 0.5 | 需改脚本或重跑代码才能更新 |
| 0 | 不可重渲染 |

### 防漂移 (4 分)

| 档位 | 判据 |
|---|---|
| 1.0 | 单一事实源机制（共享字段/占位符/from_shared/CONSTANTS 任意形式），一处改全同步 |
| 0.5 | 注释提示但代码散落 |
| 0 | 模板/脚本两处硬编码同一份知识 |

## 护栏 (10 分)

### 降级路径 + 痕迹 (4 分)

外部依赖断 → 走 fallback + 输出警告到 stderr。

### 用户语言防火墙 (3 分)

最终用户产品输出无 JSON/脚本/工具名。

### 内容合规 (3 分)

版权/原创/安全约束（如 prompt 注入防御）。

## 评估闭环 (15 分) (v3 缩至 15 分)

### evals/ 目录 (4 分)

有测试用例文件（不是空 README / placeholder）。

### rubrics 判分 (4 分)

P/R/O/M 四维或等效；含判分标准（本 skill：references/scoring_rubrics.md 档位表 + evals/rubric.md）。

### with/without 对照 (4 分)

同 prompt 带/不带 skill 双跑对比记录（evals/with_skill/ + evals/without_skill/）。

### 回归基线 (3 分) — 2026-08-17 新增 (v3 调低)

evals/baseline.json 含上次评估的预期分数。下次打分偏差 >5 必须复盘。

## 一票否决（H4）补充

### ❌ 严重违反（一票否决）

- SKILL.md 与 scripts/ 同时硬编码同一格式定义（字体/颜色/列宽/边框/合并）
- SKILL.md 与 assets/模板指向不一致（死引用、UUID 路径失效、模板文件不存在）
- SKILL.md 把确定性产物塞正文（≥30 行的 HTML/JSON/XML 模板）

### ✅ 容差（仍走六维）

- 只有 1 处硬编码，且量小（<10 行）
- SKILL.md 引用模板路径但模板已迁移到 references/
